# automate4z

**automate4z** is an open-source workflow orchestrator that erases the boundary between z/OS mainframe execution and local execution.

Distributed as **a single `a4z` binary** (Linux / macOS / Windows × amd64 / arm64), with no runtime to install on the user side — and **nothing to install on z/OS either**: the mainframe is driven through z/OSMF REST. Workflows are defined in YAML with a syntax inspired by GitHub Actions, adapted for the mainframe.

---

## Why automate4z?

COBOL teams transitioning to DevOps face a recurring problem: their modern CI/CD tools cannot talk to the mainframe. Every pipeline contains home-grown scripts that submit JCL jobs, download datasets and grep return codes — with no type safety and no observability. And the everyday questions — *what does this file contain? why did this job abend? what needs recompiling?* — remain locked behind a 3270 session.

automate4z solves this with a single YAML file, a single binary, and a consistent interface for both worlds.

## Key features

| Feature | Description |
|---------|-------------|
| **30 built-in tasks** | Shell, HTTP, filesystem, archives, notifications, JSON/YAML queries, templates, z/OS jobs and datasets — [the full catalogue](task-reference/overview) |
| **Mainframe data** | Copybooks → schemas, generated/anonymized test datasets, field-by-field inspection, dataset diff on decoded values |
| **Batch testing** | The [`tests:` block](workflow-spec/gates-et-tests): analyzed spools, assertions, JUnit report readable by Jenkins/GitLab |
| **Incremental build** | `source-scan` → `build-impact` → `zos-build`: the DBB-style pipeline, [with nothing installed on the LPAR](guides/build-and-test) |
| **DAG execution** | Step dependencies resolved automatically; independent steps run in parallel |
| **`$\{{ }}` expressions** | Context interpolation (inputs, outputs, env, runner) with built-in functions |
| **z/OSMF profiles** | LPAR connections through Zowe profiles, OS keyring or env variables; secrets never in the YAML |
| **Studio & App mode** | `a4z serve` opens a local web UI ([the Studio](studio/overview)); `a4z run --ui` opens a locked per-workflow operator surface |
| **External plugins** | Extra tasks shipped as `a4z-plugin-*` binaries, discovered in dedicated, lockable directories (`a4z plugins`) |
| **Lint + Plan** | Validate a workflow and show the execution plan without running it |
| **Single binary** | No Node.js, Python or Java required — one cross-platform executable |

## Minimal example

```yaml
apiVersion: automate4z/v1
kind: Workflow
name: hello-world

inputs:
  name:
    type: string
    default: World

steps:
  - id: greet
    run: echo "Hello, ${{ inputs.name }}!"
```

```bash
a4z run hello.yml --input name=Alice
```

## Project status

**v1.2.x — 30 stable built-in tasks.** The z/OS tasks (`zos-jobs`, `zos-datasets`, `z-deps`) are validated against z/Xplore; recent lots cover mainframe data (copybooks, test datasets, inspection, comparison), batch testing (`tests:` block + JUnit), incremental build (`source-scan` / `build-impact` / `zos-build`), the web Studio, App mode and external plugins.

See the [CHANGELOG](https://github.com/zarafa-dev-io/automate4z/blob/master/CHANGELOG.md) and the [GitHub releases](https://github.com/zarafa-dev-io/automate4z/releases) for version details.
