# Visual editor (No-code mode)

The **Code / No-code** toggle (file bar) replaces the text editor with a **visual canvas**.
The canvas and the text share the **same internal representation**: **every action rewrites
the YAML through CST primitives**, while **preserving your comments, order, and style**.

The view has three areas: the **Task catalog** on the left, then a **canvas | properties
panel** split (ratios are persisted).

:::info Saving

**Ctrl/Cmd-S** shortcut.
:::

## Task catalog

The catalog on the left lists the built-in tasks, fed by the schema, with a **Search tasks…**
box. At the top, a **special entry** **+ ui: / ui: App surface** (purple bar) adds or selects
the `ui:` block (see [Declaring an App surface](../app/declarer-ui)).

Tasks are split into **4 families** (fixed order):

| Family | Tasks |
| --- | --- |
| **z/OS Mainframe** | `zos-jobs`, `zos-datasets`, `z-deps`, `zos-db2`, `zos-endevor` |
| **Data** | `json-query`, `yaml-query`, `convert`, `assert`, `template` |
| **Files** | `fs`, `archive`, `extract` |
| **Control** | `shell`, `http`, `wait`, `notify`, `git` |

**Deferred** tasks carry a **Soon** badge and are **disabled**: **`zos-db2`** and
**`zos-endevor`**. You add a task with a **click** or by **dragging it** onto the canvas,
with its default fields.

## The canvas

The canvas (View Flow) materializes the workflow as connected nodes.

- **"Workflow" header node** (gray accent) at the top of the graph: selectable to edit
  name / description / inputs / env, and bearer of the **ui:** / **+ ui:** badge.
- **Task nodes**: one card per category (icon, name, type, live-status pill).
- **Ports**: source at the bottom → target at the top; dragging a connection creates a
  `needs`.
- **Edges**: explicit `needs` are **solid** with a **×** delete control on hover; implicit
  sequential links and the header → root link are **dashed** and **non-deletable**.
- **Insert-on-edge "+"** (Kestra-style) on each edge: opens a picker (**TaskPicker**) or
  accepts a **drop** from the catalog. A **"+"** also appears under a leaf node to add the
  next step.
- **Dragging a node onto another** **swaps** their order.
- **Toolbar**: **+ Add step**, **Delete step** / **Remove link**.

If the YAML becomes invalid, the canvas keeps the **"Last valid graph"** with an indication.

---

## Insert a task on a link

The **"+"** button in the middle of an edge **inserts a task between two tasks**: clicking
opens the **TaskPicker**, or you **drop** a task from the catalog directly onto the
**"+"**. The new task is inserted (`A → N → B`) and selected.

## Properties panel

The right-hand panel adapts to the selection.

### Step (task)

- **Editable `id`**: renaming **repoints the `needs`** and **rejects a collision**.
- **Schema-driven form**: the control depends on the field type.

| Field type | Control |
| --- | --- |
| `enum` | dropdown (select) |
| `boolean` | select |
| `number` / `integer` | number field |
| `object` / `array` | raw YAML/JSON editor |
| other | text field |

The label comes from `x-a4z.label`, an **asterisk** flags required fields, and the
description and default value appear as help.

- **Secret field** (name containing `auth`/`token`/`secret`/`key`/`password`/`credential`):
  a text field **plus** an **Insert secret…** select that inserts `${secret:NAME}`. **No
  value passes through** — only names are handled (see [Secrets](./secrets)).

### Header selected

Edit **name** / **description** / **inputs** (add/remove) / **env**.

### **ui:** badge selected

Edit the **App block**: **name** / **description** / **inputs** (annotations of existing
inputs) / **outputs** / **results** (widgets, `masking.keys`, reordering, table columns),
plus a **delete** button for the block. The `ui:` block is detailed in
[Declaring an App surface](../app/declarer-ui).

## "Workflow" node (header)

The header (everything before `steps:`) is materialized by the **"Workflow" node** at the top
of the canvas. Selecting it opens the header panel to edit **name**, **description**, the
**inputs** (add/remove), and the **environment variables** (`env`). This node also carries
the **ui:** / **+ ui:** badge to manage the App surface.
