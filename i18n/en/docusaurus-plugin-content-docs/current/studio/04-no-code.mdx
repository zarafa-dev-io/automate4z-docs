# Visual editor (No-code mode)

The **Code / No-code** toggle (file bar) replaces the text editor with a **visual
canvas**. The canvas and the text share the **same internal representation**: any
visual action **rewrites the YAML** while **preserving your comments, order and
style** (CST editing).

:::info Saving
Saving works in no-code just like in code: the **Save** button in the file bar
and the **Ctrl/Cmd-S** shortcut.
:::

---

## The canvas

- **Movable**, **selectable** nodes, with connection **ports**.
- **Connecting** two tasks (drag from one port to another) adds a `needs`
  dependency.
- **Removing** a task / a link via the toolbar (removing a task also purges the
  `needs` that referenced it).
- The **text → canvas** sync is **incremental**: an edit updates the graph without
  rearranging existing nodes. If the YAML becomes invalid, the **last valid graph**
  is kept ("Last valid graph" indication).

## Task catalog & drag-and-drop

The **catalog** lists the built-in tasks **grouped by family** (z/OS Mainframe,
Data, Files, Control), fed by the schema. You add a task with a **click** or by
**dragging it onto the canvas**, with its **default fields**. **Deferred** tasks
(`zos-db2`, `zos-endevor`) appear **disabled** ("Soon"). A **search** filters the
catalog.

## Insert a task on a link

A **"+"** button in the middle of each link lets you **insert a task between two
tasks** (Kestra-style): clicking opens a **picker**, or you **drop** a task from
the catalog directly onto the "+". The new task is inserted (`A → N → B`) and
selected.

## Properties panel

Selecting a task opens a **schema-driven form**: one field per input (dropdown for
`enum`, booleans, numbers, text) with **required-field validation**. Any change
flows back to the YAML. For a **secret-typed field**, the panel offers the
**known secrets** (names only) and inserts the **`${secret:NAME}`** format. The
**`id`** field is **renamable** (`needs` dependencies are repointed automatically).

## Workflow header

The **header** (everything before `steps:`) is materialized by a **"Workflow"
node** at the top of the canvas. Selecting it opens a panel to edit **name**,
**description**, the **inputs** (typed parameters: type, required, default,
description — add/remove) and the **environment variables** (`env`). New blocks
are inserted **before `steps:`**.
