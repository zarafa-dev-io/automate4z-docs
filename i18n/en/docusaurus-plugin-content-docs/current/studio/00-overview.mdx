# Studio — the web interface

**Studio** is automate4z's web interface, served locally by the `a4z` binary.
It lets you edit, validate, run and monitor workflows — in **text** mode
(YAML editor) or **no-code** mode (visual canvas) — with nothing else to install: the
SPA is **embedded in the binary**.

## Launching Studio

```bash
a4z serve
```

`a4z serve` starts a local web server and **opens the browser** on the interface.

| Option | Default | Description |
|--------|---------|-------------|
| `--host` | `127.0.0.1` | Listening interface (loopback only by default) |
| `--port` | `4500` | TCP port (`0` picks a free port) |
| `--workspace` | current directory | Workspace served (workflow folder) |
| `--no-open` | — | Do not open the browser automatically |

### Security model

- The server **binds to `127.0.0.1`** by default. Any non-loopback `--host` prints a
  warning (there is **no network authentication**).
- A random **session token** is generated and included in the opened URL; any request
  without a valid token gets `401`. Mutating methods are CSRF-protected (token required
  in a header, loopback `Origin`).
- `a4z serve` is a **one-shot binary**: no daemon, no service.

## Getting around: header & sidebar

Studio is organized around a persistent **header** and an icon **sidebar**.

The **header** holds:

- the **`a4z` automate4z Studio** logo;
- in the center, the **workspace switcher** (open / switch between several folders — see
  [Workspaces](./espaces));
- on the right, the **theme toggle** (light / dark, remembered) and the binary
  **version** (`a4z <version> · core <version>`).

| **Secrets** | The [Secrets](./secrets) panel (OS keychain, write-only). |
| **Settings** | The [settings & profiles](./settings) (history retention, AI, notifications…). |

## The Workflows list

The **Workflows** section lists the workflow files discovered in the workspace
(extension **`.a4z.yaml` / `.a4z.yml`**, recursive scan ignoring hidden folders and
`.automate4z`). A recognized but invalid workflow is **still listed**, flagged with a ⚠.

| Column | Content |
|--------|---------|
| **Name / id** | Workflow name + file path (click = open). |
| **Last execution** | Date of the last run, or "never run". |
| **Status** | Last status, colored. |
| **Statistics** | Number of runs, success %, **sparkline** of the last 10. |
| **Actions** | **Run** (▶), **favorite** (★, capped at 5), **Delete** (with confirmation). |

A **Filter workflows…** field filters the list, **Refresh** re-reads the workspace (a
workflow created outside Studio only appears after a refresh), and **+ New workflow**
creates one from a minimal valid template.

## The workflow page

Opening a workflow shows a **tabbed** page, with a `Workflows / <name> / <tab>`
breadcrumb. On the right of the tab bar: the **favorite** (★) and the **Run** button
(see [Running & monitoring](./execution)).

| Tab | Content |
|-----|---------|
| **Overview** | Workflow summary: KPIs over the chosen interval (7d/30d/90d), a **Workflow** card (name, file, description, step count), **Last execution**, and a topology preview. |
| **Topology** | The [DAG view](./editeur#topology) of the execution graph, **read-only** (live statuses during a run). |
| **Executions** | The [run history](./historique) filtered on this workflow. |
| **Editor** | The [workflow editor](./editeur) (**Code** and **No-code** modes). |

## Two ways to edit

| Mode | Description |
|------|-------------|
| **Code** | [YAML editor](./editeur) (CodeMirror) with validation, autocomplete and a read-only DAG view. |
| **No-code** | [Visual canvas](./no-code): task catalog, drag-and-drop, properties panel, header editing — all of which rewrite the YAML while preserving your comments. |

Both views share the **same internal representation**: switching between them never
loses content.
