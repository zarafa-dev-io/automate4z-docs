# Workflow editor (Code mode)

**Code** mode shows the YAML editor on the left and a **two-tab side panel**
(**Topology** / **Documentation**) on the right. A **resizable split** separates them.

At the top, the **file bar** gathers the **Code / No-code** toggle, the validity indicator
**✓ schema valid** / **✕ N error(s)**, the save state **● Modified** / **Saved** (and
**Saving…** while writing), and the **Save** button (disabled until the file is modified).
The **Ctrl/Cmd-S** shortcut saves.

## Editing

The editor is built on **CodeMirror 6**: line numbers, **folding**, and undo/redo
**history**.

**Highlighting** distinguishes keys, strings (green), numbers and booleans (amber), and
comments (gray, italic). Two reference forms are **highlighted** so you can spot them at a
glance:

| Reference | Role | Highlight |
| --- | --- | --- |
| `${secret:…}` | Secret injected at run time (see [Secrets](./secrets)) | **bold amber** |
| `${{ … }}` | Evaluated expression | **purple** |

:::info Verbatim write
Saving (`Save` or **Ctrl/Cmd-S**) is **atomic** and **verbatim**: your comments, key order,
and style are **preserved**, with no re-serialization of the document.
:::

### Conflict detection

On save, `POST /api/save` compares a **`revision`** (a hash of the opened content) with the
one on disk. On a mismatch, the API returns **409** **without writing**, and a
**"This file changed on disk since you opened it"** banner offers **Reload** (load the
on-disk version) or **Overwrite** (replace it with your version).

## Schema-driven autocomplete

Completions come from the **binary's schema** (`GET /api/tasks`), so they always match the
installed version:

- **task types** on `uses:`,
- **fields** on `with:` depending on the task,
- workflow and step **keys**.

## Validation & the Problems panel

The content is continuously validated via `POST /api/validate`, which covers:

- **YAML parsing**,
- **schema conformance**,
- **DAG cycles**,
- **warnings** (non-blocking) for every **undefined** `${secret:NAME}`.

**Diagnostics** appear **inline** in the gutter and are gathered in a **Problems panel**
below the editor: a click **jumps to the line**. The codes match those of `a4z lint` (see
the [CLI reference](../cli-reference)) — for example `A4Z-PARSE-001`, `A4Z-VAL-001`,
`A4Z-DAG-001` / `A4Z-DAG-002`, `A4Z-SECRET-001`. The **✓ schema valid** / **✕ N error(s)**
indicator in the file bar summarizes the state.

## Side panel: Topology & Documentation

The right-hand panel offers two tabs.

### Topology

The **DAG** (execution graph), **read-only**: steps, `needs` dependencies, and implicit
sequential dependencies. During a run, each node reflects the task's **live status**,
overlaid on the graph.

:::tip Visual editing
**Topology** is read-only. To **modify** the graph (add/remove tasks, draw dependencies),
switch to [No-code mode](./no-code).
:::

### Documentation

The **Documentation** tab shows the doc for the task **under the cursor**, depending on the
state:

| State | Display |
| --- | --- |
| Cursor outside a task | "Place the cursor inside a task…" |
| Loading | loading indicator |
| Unknown type | error message with "Did you mean … ?" |
| Recognized task | **type** + **summary** + **Parameters** (derived from the schema, required fields flagged) + YAML **Examples** |

:::note Air-gapped
All documentation comes from the **binary**: no network access is required.
:::
