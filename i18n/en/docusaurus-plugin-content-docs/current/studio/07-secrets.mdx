# Secrets

The **Secrets** panel (sidebar) manages the credentials your workflows need — z/OSMF token,
SSH key, SMTP password, LLM API key. It is **write-only**, backed by the **OS keychain**
(subtitle "write-only · OS keychain"): a value you enter is encrypted by the operating system
and **never** returned to the interface or logged.

Secrets are **global**: unlike workflows and executions, they are **not** isolated per
workspace. A credential is usually common to a single user's projects — see
[Workspaces](./espaces).

:::info Write-only by design
The server exposes **no** endpoint able to read a value back. `GET` returns only **names** and
**non-secret metadata** (type, rotation, expiration, last-updated date). The value travels only
once, from the browser to the keychain, in a request **body** — never in a URL, never in a log.
:::

---

## The card grid

Each secret is a **card**. It shows:

- the **name** (in mono);
- a **type badge**;
- a **rotation badge** ("rotation · N days") when a rotation is configured;
- an **expiration badge** — "expired", "expires today" or "expires in N days". The alert turns
  **amber** at **14 days or fewer** before the deadline;
- a card footer "● stored · &lt;updated date&gt;";
- the **Edit** and **Delete** buttons (deletion asks for **inline confirmation**).

---

## Create or edit a secret

The **+ New secret** button — or **Edit** on a card — opens the form:

| Field | Detail |
|-------|--------|
| **Name** | Secret identifier, constrained by `^[A-Z0-9_]{1,64}$`. **Not editable** when editing. |
| **Type** | **credential**, **ssh-key**, **key** or **token**. |
| **Rotation** | Rotation period, in **days** (optional). Feeds the "rotation · N days" badge. |
| **Expires on** | Expiration date (optional). Feeds the expiration badge and the amber alert. |
| **Value** | The secret value — a **password** field, **write-only**. |

On save, the interface sends `POST /api/secrets` (response `204`), with the value carried in the
request **body**, never in the URL. Deletion calls `DELETE /api/secrets/{name}`.

:::note Rename?
The **name** is the secret's key in the keychain: it cannot be changed afterwards. To "rename",
create a new secret and delete the old one.
:::

## Using a secret in a workflow

You never paste a value into a workflow: you **reference** a secret by name, with the
**`${secret:NAME}`** syntax. In the [YAML editor](./editeur), those references are **highlighted
in amber** to set them apart from a literal string.

```yaml
tasks:
  - id: fetch
    type: zosmf
    with:
      token: ${secret:ZOSMF_TOKEN}
```

At run time, the binary **resolves** the reference by reading the keychain — the value appears
neither in the YAML, nor in the [history](./historique), nor in the logs.

:::tip App mode — pre-provisioned secrets
In [App mode](../app/overview), secrets are **pre-provisioned** by IT on the machine and resolved
by the binary. The operator **never enters** a secret: the App surface does not even expose the
Secrets panel.
:::

Every panel operation exists on the command line through `a4z secrets` (create, list names and
