# Run a workflow

From the editor, the **run panel** lets you launch the open workflow
**in-process** (no `a4z` subprocess).

## Refusals & parameters

Before launching, the server checks:

- **invalid workflow** → the run is refused and the errors are pointed out;
- **missing required parameters** → a **form** prompts for the values (`inputs`);
- **undefined `${secret:NAME}`** → the run is refused.

## Live monitoring

Once launched, **live monitoring** consumes the engine's **NDJSON** event stream
and shows the lifecycle as it happens:

- per-task status, **RC** (return/condition code), `n/total` progress, durations;
- **scrolling logs** (with secret masking inherited from the stream);
- final status + **overall RC**.

The **DAG view reflects each node's live status** (success / failure / cancelled /
skipped / running), and a **Gantt chart** updates with a "now" marker (see
[History & Gantt](./historique)).

## Results & artifacts

When the run finishes, the **per-task outputs** and the produced **artifacts**
(files detected in the workspace, e.g. an archive) appear with **download links**
— including for a failed run (partial outputs remain viewable).
