# Run history

History relies on the **same component** in two places: the **Executions** section of
the sidebar (all workflows in the space) and a workflow's **Executions** tab (filtered
to its path). The layout is a **master / detail** backed by a **SQLite** database
`.automate4z/runs.db` (one per space).

---

## Run list

The list (left) shows the most recent runs first. It offers a **Filter runs…** field
and a refresh button. Each row shows:

- a **status icon**;
- the **workflow name**;
- the **duration** and **timestamp**;
- the **trigger** (`studio` or `cli`).

Deletion is per row, with **confirmation**. It is **refused (409) while the run is still
in progress**.

:::note Under the hood
The list calls `GET /api/runs?limit=` (**200** by default, most recent first).
:::

## Run detail

Selecting a run shows its **detail** (right). The header carries the **status icon**,
the **name** and the run **id**, plus the **Resume** and **Relaunch** actions.

### Sub-tabs

They only appear when there is more than the **Overview** to show:

| Sub-tab | Shown if… | Content |
| --- | --- | --- |
| **Overview** | always | Run summary (see below). |
| **Outputs** | the run has outputs | Per-task outputs. |
| **Inputs** | the run has inputs | Recorded `inputs` values. |
| **Logs** | there are logs | Persisted lines, grouped by step. |
| **Timing** | there are steps | Per-step duration vs historical median. |
| **Results** | the workflow declares `ui.results` | Result view defined by the workflow. |

**Overview** gathers: **Status**, **Exit code** (red if ≠ 0), **Duration**, **Trigger**,
**Started**, a link to the **Workflow**, the **Timeline (Gantt)**, the **Tasks** section
and the **Artifacts** section.

The **Tasks** section lists tasks **in execution order**: status, id, name, **reason**
(e.g. *if-false*, *needs-not-met*), duration and **RC**. **Artifacts** are downloadable
(name + size).

The **Logs** sub-tab groups lines **by step** and offers a **DEBUG** toggle (debug lines
are hidden by default). The **Timing** sub-tab compares each step's duration to its
**historical median**.

## Gantt chart

The **Timeline (Gantt)** represents each task as a **bar** positioned by its **start**
and **duration**, colored by status. **Parallel tasks overlap** faithfully, and the
**offending task** is highlighted. For a running run, the Gantt updates **live** with a
**"now"** marker.

## Relaunch

**Relaunch** reopens the workflow and re-runs it with the run's **recorded inputs**. The
action is **disabled if the workflow path is unknown**.

---

## Resume — resume after failure

The **Resume** button is **only shown if the run did not succeed**. Its label becomes
**"Resume from &lt;task&gt;"** when resuming is possible; otherwise it stays **"Resume"
disabled**, with the reason in a tooltip.

A run is **resumable if and only if**:

- it **did not already succeed**;
- its **workflow file still exists**;
- **at least one step succeeded**.

The **resume task** is the **first non-successful step** in execution order. The server
re-runs the workflow by **re-injecting the already-successful steps**: those are **not
replayed**.
