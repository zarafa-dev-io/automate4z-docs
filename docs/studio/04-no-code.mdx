# Éditeur visuel (mode No-code)

La bascule **Code / No-code** (barre de fichier) remplace l'éditeur texte par un **canvas
visuel**. Le canvas et le texte partagent la **même représentation interne** : **toute
action réécrit le YAML via des primitives CST**, en **préservant vos commentaires, l'ordre
et le style**.

La vue se compose de trois zones : le **Task catalog** à gauche, puis un **split
canvas | panneau de propriétés** (les ratios sont persistés).

## Task catalog

Le catalogue à gauche liste les tâches intégrées, alimenté par le schéma, avec une recherche
**Search tasks…**. En tête, une **entrée spéciale** **+ ui: / ui: App surface** (barre
violette) permet d'ajouter ou de sélectionner le bloc `ui:` (voir [Déclarer une surface
App](../app/declarer-ui)).

Les tâches sont réparties en **4 familles** (ordre fixe) :

| Famille | Tâches |
| --- | --- |
| **Mainframe z/OS** | `zos-jobs`, `zos-datasets`, `z-deps`, `zos-db2`, `zos-endevor` |
| **Données** | `json-query`, `yaml-query`, `convert`, `assert`, `template` |
| **Fichiers** | `fs`, `archive`, `extract` |
| **Contrôle** | `shell`, `http`, `wait`, `notify`, `git` |

Les tâches **différées** portent un badge **Soon** et sont **désactivées** : **`zos-db2`**
et **`zos-endevor`**. On ajoute une tâche par **clic** ou par **glisser-déposer** sur le
canvas, avec ses champs par défaut.

## Le canvas

Le canvas (Vue Flow) matérialise le workflow sous forme de nœuds connectés.

- **Nœud d'en-tête « Workflow »** (accent gris) en tête du graphe : sélectionnable pour
  éditer name / description / inputs / env, et porteur du badge **ui:** / **+ ui:**.
- **Nœuds de tâche** : une carte par catégorie (icône, nom, type, pill de statut live).
- **Ports** : source en bas → cible en haut ; tirer une connexion crée un `needs`.
- **Arêtes** : les `needs` explicites sont en **trait plein** avec un **×** de suppression
  au survol ; les liens séquentiels implicites et le lien en-tête → racine sont en
  **pointillés** et **non supprimables**.
- **Insert-on-edge « + »** (façon Kestra) sur chaque arête : ouvre un sélecteur
  (**TaskPicker**) ou accepte un **drop** du catalogue. Un **« + »** apparaît aussi sous un
  nœud feuille pour ajouter l'étape suivante.
- **Glisser un nœud sur un autre** échange leur ordre (**swap**).
- **Barre d'outils** : **+ Add step**, **Delete step** / **Remove link**.

Si le YAML devient invalide, le canvas conserve le **« Last valid graph »** avec une
indication.

## Insérer une tâche sur un lien

Le bouton **« + »** au milieu d'une arête **insère une tâche entre deux tâches** : cliquer
ouvre le **TaskPicker**, ou l'on **dépose** une tâche du catalogue directement sur le
**« + »**. La nouvelle tâche est insérée (`A → N → B`) et sélectionnée.

## Panneau de propriétés

Le panneau de droite s'adapte à la sélection.

### Étape (tâche)

- **`id` éditable** : le renommage **repointe les `needs`** et **rejette une collision**.
- **Formulaire piloté par le schéma** : le contrôle dépend du type du champ.

| Type de champ | Contrôle |
| --- | --- |
| `enum` | liste déroulante (select) |
| `boolean` | select |
| `number` / `integer` | champ numérique |
| `object` / `array` | éditeur YAML/JSON brut |
| autre | champ texte |

Le libellé provient de `x-a4z.label`, un **astérisque** signale les champs requis, et la
description ainsi que la valeur par défaut apparaissent en aide.

- **Champ secret** (nom contenant `auth`/`token`/`secret`/`key`/`password`/`credential`) :
  champ texte **+** un select **Insert secret…** qui insère `${secret:NOM}`. **Aucune valeur
  ne transite** — seuls les noms sont manipulés (voir [Secrets](./secrets)).

### En-tête sélectionné

Édition de **name** / **description** / **inputs** (ajout/suppression) / **env**.

### Badge **ui:** sélectionné

Édition du **bloc App** : **name** / **description** / **inputs** (annotations des inputs
existants) / **outputs** / **results** (widgets, `masking.keys`, réordonnancement, colonnes
de table), plus un bouton de **suppression** du bloc. Le détail du bloc `ui:` est décrit dans
[Déclarer une surface App](../app/declarer-ui).

## Nœud « Workflow » (en-tête)

L'en-tête (tout ce qui précède `steps:`) est matérialisée par le **nœud « Workflow »** en
tête du canvas. Le sélectionner ouvre le panneau d'en-tête pour éditer **name**,
**description**, les **inputs** (ajout/suppression) et les **variables d'environnement**
(`env`). Ce nœud porte également le badge **ui:** / **+ ui:** pour gérer la surface App.
