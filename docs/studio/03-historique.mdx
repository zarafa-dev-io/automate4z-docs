# Historique des exécutions

L'onglet **Executions** liste les runs **persistés** (par espace de travail), les plus
récents en tête, **filtrables** (workflow, statut, déclencheur, id).

## Détail d'un run

Sélectionner un run affiche son **détail** : statut, **RC**, durée, **paramètres**,
déclencheur, et la liste des **tâches** (statut, RC, durée).

Le détail est organisé en **onglets** — Overview, puis, selon ce que le run a
enregistré : **Outputs**, **Inputs**, **Logs**, **Timing** et **Results**.

### Onglet Outputs

Quand le workflow déclare un bloc `outputs:`, l'onglet **Outputs** (entre
Overview et Logs) liste ses **outputs de niveau workflow** résolus — les valeurs
nommées calculées à la fin du run à partir des sorties de step (voir
[Outputs du workflow](../workflow-spec/05-outputs-defaults.mdx)). Les clés sont
triées et les valeurs **masquées** (secrets remplacés par `***`). Un run dont le
workflow ne déclare pas d'`outputs:` n'a pas cet onglet.

## Diagramme de Gantt

Le détail inclut une **chronologie (Gantt)** : chaque tâche est une barre positionnée par
son **début** et sa **durée**, colorée par statut. Les tâches **parallèles se chevauchent**
fidèlement, et la **tâche fautive** est mise en évidence. Pour un run en cours, le Gantt se
met à jour **en direct** avec un repère **« maintenant »**.

## Relancer

Depuis le détail, **Relancer** rouvre le workflow et le **réexécute** avec les paramètres
enregistrés.

---

## Reprendre sur incident

Pour un run **interrompu** (échec, arrêt), Studio propose **« Reprendre depuis &lt;tâche&gt; »**
en s'appuyant sur l'état persisté : les tâches **déjà réussies ne sont pas rejouées**, et le
suivi en direct reprend. Si le run n'est **pas reprenable** (déjà réussi, fichier disparu,
aucune tâche réussie), l'option est **désactivée avec une explication**.
