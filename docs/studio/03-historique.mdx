# Historique des exécutions

L'historique s'appuie sur le **même composant** à deux endroits : la section
**Exécutions** de la barre latérale (tous les workflows de l'espace) et l'onglet
**Executions** d'un workflow (filtré sur son chemin). L'affichage est un **maître /
détail** adossé à une base **SQLite** `.automate4z/runs.db` (une base par espace).

---

## Liste des runs

La liste (à gauche) présente les runs les plus récents en tête. Elle offre un champ
**Filter runs…** et un bouton de rafraîchissement. Chaque ligne affiche :

- une **icône de statut** ;
- le **nom du workflow** ;
- la **durée** et l'**horodatage** ;
- le **trigger** (`studio` ou `cli`).

La suppression se fait ligne par ligne, avec **confirmation**. Elle est **refusée
(409) tant que le run est encore en cours**.

:::note Sous le capot
La liste appelle `GET /api/runs?limit=` (**200** par défaut, plus récent d'abord).
:::

## Détail d'un run

Sélectionner un run affiche son **détail** (à droite). L'en-tête reprend l'**icône de
statut**, le **nom** et l'**id** du run, ainsi que les actions **Resume** et
**Relaunch**.

### Sous-onglets

Ils n'apparaissent que lorsqu'il y a plus que l'**Overview** à montrer :

| Sous-onglet | Affiché si… | Contenu |
| --- | --- | --- |
| **Overview** | toujours | Synthèse du run (voir ci-dessous). |
| **Outputs** | le run a des sorties | Sorties par tâche. |
| **Inputs** | le run a des entrées | Valeurs `inputs` enregistrées. |
| **Logs** | il y a des logs | Lignes persistées, groupées par étape. |
| **Timing** | il y a des étapes | Durée par étape vs médiane historique. |
| **Results** | le workflow déclare `ui.results` | Vue de résultats définie par le workflow. |

**Overview** rassemble : **Status**, **Exit code** (en rouge s'il est ≠ 0),
**Duration**, **Trigger**, **Started**, un lien vers le **Workflow**, la **Timeline
(Gantt)**, la section **Tasks** et la section **Artifacts**.

La section **Tasks** liste les tâches **en ordre d'exécution** : statut, id, name,
**reason** (par ex. *if-false*, *needs-not-met*), durée et **RC**. Les **Artifacts**
sont téléchargeables (nom + taille).

Le sous-onglet **Logs** groupe les lignes **par étape** et propose un toggle **DEBUG**
(les lignes de debug sont masquées par défaut). Le sous-onglet **Timing** compare la
durée de chaque étape à sa **médiane historique**.

### Onglet Outputs

Quand le workflow déclare un bloc `outputs:`, l'onglet **Outputs** (entre
Overview et Logs) liste ses **outputs de niveau workflow** résolus — les valeurs
nommées calculées à la fin du run à partir des sorties de step (voir
[Outputs du workflow](../workflow-spec/05-outputs-defaults.mdx)). Les clés sont
triées et les valeurs **masquées** (secrets remplacés par `***`). Un run dont le
workflow ne déclare pas d'`outputs:` n'a pas cet onglet.

## Diagramme de Gantt

La **Timeline (Gantt)** représente chaque tâche par une **barre** positionnée selon son
**début** et sa **durée**, colorée par statut. Les tâches **parallèles se chevauchent**
fidèlement, et la **tâche fautive** est mise en évidence. Pour un run en cours, le Gantt
se met à jour **en direct** avec un repère **« now »**.

## Relaunch

**Relaunch** ré-ouvre le workflow et le relance avec les **inputs enregistrés** du run.
L'action est **désactivée si le chemin du workflow est inconnu**.

---

## Resume — reprise sur incident

Le bouton **Resume** n'est **affiché que si le run n'a pas réussi**. Son libellé devient
**« Resume from &lt;tâche&gt; »** lorsque la reprise est possible ; sinon il reste
**« Resume » désactivé**, avec la raison en infobulle.

Un run est **résumable si et seulement si** :

- il **n'a pas déjà réussi** ;
- son **fichier workflow existe encore** ;
- **au moins une étape a réussi**.

La **tâche de reprise** est la **première étape non réussie** en ordre d'exécution. Le
serveur ré-exécute le workflow en **réinjectant les étapes déjà réussies** : celles-ci
**ne sont pas rejouées**.
