# Studio — l'interface web

**Studio** est l'interface web d'automate4z, servie localement par le binaire `a4z`.
Elle permet d'éditer, valider, exécuter et suivre des workflows — en mode **texte**
(éditeur YAML) ou **no-code** (canvas visuel) — sans rien installer de plus : la SPA
est **embarquée dans le binaire**.

## Lancer Studio

```bash
a4z serve
```

`a4z serve` démarre un serveur web local et **ouvre le navigateur** sur l'interface.

| Option | Défaut | Description |
|--------|--------|-------------|
| `--host` | `127.0.0.1` | Interface d'écoute (loopback uniquement par défaut) |
| `--port` | `4500` | Port TCP (`0` choisit un port libre) |
| `--workspace` | répertoire courant | Espace de travail servi (dossier de workflows) |
| `--no-open` | — | Ne pas ouvrir le navigateur automatiquement |

### Modèle de sécurité

- Le serveur **se lie à `127.0.0.1`** par défaut. Tout `--host` non-loopback affiche un
  avertissement (il n'y a **pas d'authentification réseau**).
- Un **jeton de session** aléatoire est généré et inclus dans l'URL ouverte ; toute
  requête sans jeton valide reçoit `401`. Les méthodes mutantes sont protégées contre le
  CSRF (jeton exigé dans un en-tête, `Origin` loopback).
- `a4z serve` est un **binaire one-shot** : pas de daemon, pas de service.

## Se repérer : en-tête & barre latérale

Studio s'organise autour d'un **en-tête** persistant et d'une **barre latérale** d'icônes.

L'**en-tête** regroupe :

- le logo **`a4z` automate4z Studio** ;
- au centre, le **sélecteur d'espace de travail** (ouvrir / basculer entre plusieurs
  dossiers — voir [Espaces de travail](./espaces)) ;
- à droite, la **bascule de thème** (clair / sombre, mémorisée) et la **version** du
  binaire (`a4z <version> · core <version>`).

La **barre latérale** donne accès aux cinq surfaces de Studio :

| Section | Rôle |
|---------|------|
| **Dashboard** | [Tableau de bord](./dashboard) d'accueil : KPIs, tendances et derniers runs, tous workflows confondus. |
| **Workflows** | La **liste des workflows** de l'espace (voir plus bas). |
| **Exécutions** | L'[historique des runs](./historique) (tous workflows), avec détail, Gantt et reprise. |
| **Secrets** | Le panneau [Secrets](./secrets) (trousseau de l'OS, en écriture seule). |
| **Settings** | Les [réglages & profils](./settings) (rétention d'historique, IA, notifications…). |

## La liste des Workflows

La section **Workflows** liste les fichiers de workflow découverts dans l'espace de
travail (extension **`.a4z.yaml` / `.a4z.yml`**, scan récursif ignorant les dossiers
cachés et `.automate4z`). Un workflow reconnu mais invalide est **listé quand même**,
signalé par un ⚠.

| Colonne | Contenu |
|---------|---------|
| **Name / id** | Nom du workflow + chemin de fichier (clic = ouvrir). |
| **Last execution** | Date du dernier run, ou « never run ». |
| **Status** | Dernier statut, coloré. |
| **Statistics** | Nombre de runs, % de succès, **sparkline** des 10 derniers. |
| **Actions** | **Run** (▶), **favori** (★, plafonné à 5), **Delete** (avec confirmation). |

Un champ **Filter workflows…** filtre la liste, **Refresh** relit l'espace (un workflow
créé hors Studio n'apparaît qu'après relecture), et **+ New workflow** en crée un depuis
un gabarit minimal valide.

## La page d'un workflow

Ouvrir un workflow affiche une page à **onglets**, avec un fil d'Ariane
`Workflows / <nom> / <onglet>`. À droite de la barre d'onglets : le **favori** (★) et le
bouton **Run** (voir [Exécution & suivi](./execution)).

| Onglet | Contenu |
|--------|---------|
| **Overview** | Synthèse du workflow : KPIs sur l'intervalle choisi (7d/30d/90d), carte **Workflow** (name, fichier, description, nombre de steps), **Last execution**, et un aperçu de la topologie. |
| **Topology** | La [vue DAG](./editeur#topology) du graphe d'exécution, **en lecture seule** (statuts en direct pendant un run). |
| **Executions** | L'[historique des runs](./historique) filtré sur ce workflow. |
| **Editor** | L'[éditeur de workflow](./editeur) (modes **Code** et **No-code**). |

## Deux façons d'éditer

| Mode | Description |
|------|-------------|
| **Code** | [Éditeur YAML](./editeur) CodeMirror avec validation, autocomplétion et vue DAG en lecture seule. |
| **No-code** | [Canvas visuel](./no-code) : catalogue de tâches, glisser-déposer, panneau de propriétés, édition de l'entête — le tout réécrit le YAML en préservant vos commentaires. |

Les deux vues partagent la **même représentation interne** : passer de l'une à l'autre
ne perd jamais le contenu.
